# Test resumes (DP-15)

20 resumes for testing HireLens, generated by `backend/scripts/generate_test_resumes.py`.
Every name, email, phone number, employer and school here is made up - there is no real
personal data in this folder.

Regenerate the set (for example after changing a generator detail) with:

```bash
cd backend
uv run python -m scripts.generate_test_resumes
```

## Good resumes (`good_*`)

11 resumes with no layout problems: single column, plain text, real section headings
(cycling through different real-world phrasings, like "Work Experience" vs "Experience" -
see `app/sections.py`'s recognized headings). A few deliberately leave out one section
(`good_03` has no summary, `good_08` has no education) so the set also tests section
detection on resumes that are simply incomplete, not just badly formatted.

## ATS-unfriendly resumes (`bad_*`)

9 resumes, each with a specific, deliberate problem an ATS - and HireLens' own `ats-score`
and `format-checks` endpoints - should catch:

| File | Problem |
| --- | --- |
| `bad_01_two_column.pdf` | Two-column layout |
| `bad_02_table_layout.pdf` | Experience laid out in a table |
| `bad_03_table_layout.docx` | Experience laid out in a table |
| `bad_04_with_photo.pdf` | Embedded photo |
| `bad_05_with_photo.docx` | Embedded photo |
| `bad_06_text_box_contact.docx` | Contact details inside a text box |
| `bad_07_no_headings.pdf` | No recognizable section headings at all |
| `bad_08_header_only_contact.docx` | Email and phone only in the page header |
| `bad_09_scanned_no_text.pdf` | No text layer at all, as if scanned from a photo |

`bad_09` is the one resume `check_extraction.py` can't read - that's deliberate, it's there
to exercise the "scanned image" failure path, not the format checks. The other 19 are all
readable (95%, clearing DP-18's 90% target), and `check_sections.py`/`check_format` together
flag every `bad_*` file above with at least one real problem.
